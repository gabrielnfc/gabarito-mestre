## 1. Intenção

O Gabarito Mestre é um plugin de Claude Code que, instalado num repositório, vira o **engenheiro sênior residente**: traz o processo de planejamento e entrega (Fluxo Gabarito), executa uma spec aprovada em loop autônomo com subagents paralelos até a homologação, e só chama o humano quando não consegue, quando há impacto financeiro ou estrutural, ou quando a spec precisa mudar. O usuário não precisa lembrar do que é core em engenharia: o padrão vem embutido, com explicação didática.

**Por quê agora [V]:** a 1.1.0 entregou produto em 2 dias; desde 25/09 nenhuma linha de produto entrou — GM-7 e GM-8 somaram ~15 mil linhas de documentação, ~770 achados de review e zero código (ledgers GM-7/GM-8). As travas atuais são regex que simulam shell: 71 ms de CPU e ~29 processos por comando Bash, escape hatch autodeclarável, falsos negativos em `git push --force`, `vercel --prod`, MCP e `Edit/Write`, falsos positivos em `rm -rf .next` e SQL local (auditoria 2026-10-31). O dono, usuário diário, virou "babá do Claude".

## 2. Metas, não-metas, anti-metas

**Metas**
1. Autonomia confiável: spec aprovada → código em homologação sem intervenção, com tudo visível.
2. Produção nunca alterada sem permissão prévia (ambiente preparado + política de entrega) ou nominal; todo acesso a produção exibido na UI.
3. Testes sem redundância: cada teste roda num lugar só, no momento mais barato; banco pré-montado; CI só quando precisa.
4. Token sem desperdício: contexto fixo ≤ 2k tokens por sessão; pouso automático na fronteira da task; subagents recebem ponteiros.
5. Didático: toda ação explica o quê, por quê e como seguir, em linguagem de pessoa.
6. Fluido: onboarding em ≤ 5 perguntas; painel que mostra o estado sem comando.

**Não-metas (dono: Gabriel · gatilho para reabrir):** multi-dev simultâneo na mesma entrega (time ≥ 3 devs no mesmo Epic); assinatura criptográfica de aprovação (1º incidente de autoria contestada); stacks fora de Node/TS + Postgres (1º repo do time em outra stack); sincronização bidirecional com ClickUp (E5 estável em 3 repos); substituir o Horizon (nunca — fronteira em §7).

**Anti-metas (falha mesmo funcionando):** o agente parar em silêncio; bloquear operação legítima em teste ou homolog; pedir ao humano algo que a spec já responde; processo que produza mais documentação que código; regra de qualidade que o agente possa autodeclarar cumprida.

## 3. Fatos que fundamentam (não reabrir sem fato novo)

- **M1 Plataforma [V doc code.claude.com, medido 2026-10-31]:** hooks aceitam matcher de MCP (`mcp__<srv>__<tool>`), `Edit|Write|Read|Grep`, filtro `if: "Bash(git push *)"`; input traz `agent_id` só em subagent (`agent_type` também aparece em sessão `--agent`, logo não identifica subagent); `permissionDecision: ask` pede ao humano (negado em `-p` e `dontAsk`); `allow` de hook **suprime o prompt nativo**; sem managed settings nem login Team/Enterprise, um mod pode aprovar o que `deny` recusou; `systemMessage` é visível ao humano, `additionalContext` só ao modelo. Plugin **não** distribui `permissions`, `sandbox` nem `statusLine` (só `agent`, `subagentStatusLine`); hooks no frontmatter de agente de plugin são ignorados. Mods (`modules` em hooks.json) desenham Pane, AbovePrompt e toast; ativos por padrão no terminal desde 2.1.287; API marcada "may change without notice"; sob org gerenciada `classic.*` de plugin de usuário não roda.
- **M2 Mods [V spikes T0 GM-8, medido 2026-10-19, build 2.1.304]:** `$.state` zera em `/clear`; `session.start` não dispara em `/clear`; `/clear` + `prompt.submit` retomam 10/10; append com lock p95 36 ms; subagent inicia dentro de `next(e)`; `agentId` ausente para o orquestrador. Revalidar a cada build.
- **M3 Travas [V auditoria, medido 2026-10-31]:** hatch textual liberou `rm -rf src` com motivo "qualquer coisa aqui"; DESTRUCTIVE e PRODUCTION se liberam mutuamente; prefixo libera comando composto inteiro; nada fora de Bash é visto.
- **M4 Esteira real [V recon true_force, 200 runs de 21/09 a 30/10, medido 2026-10-31]:** 76% de runs vermelhos em PR (dependabot 60% dos runs, 100% falha); 30,8 job-min por run; unit e lint rodam 2×; `npm ci`+`build` em 5 jobs; Supabase start + migrate 3× por PR; sem `concurrency`; sem feature flags; minutos não cobrados — gargalo é tempo e vermelho, não dinheiro. Self-hosted: não.
- **M5 Horizon [V recon, lido 2026-10-31]:** raia por Epic (Spike→Pacote) não entregue; sem schema de pacote; D-H120/121 (decididas por Fable delegado) colidem com §7 e precisam ser reabertas pelo dono.
- **M6 Comunidade [V GitHub, lido 2026-10-31]:** claude-hud 29k★ = texto minimal + barras; mods "pet" em pixel são nicho; árvore orquestrador→agente (claude-agent-tree) e barra de plano (claude-deck) são o idioma reconhecido.

## 4. Princípios

1. **Fatos, não hipóteses.** Premissa externa vira spike antes de virar requisito. Número inventado não entra em spec, painel nem ETA.
2. **Sênior embutido.** Definição de pronto, esteira, flags, migrations seguras, rollback vêm do plugin; o usuário muda se quiser.
3. **Visível ≠ pergunta.** Mostrar sempre; perguntar só nos três casos de §6.5.
4. **Tighten-only.** O piso de qualidade (§6.4) nunca afrouxa; spec só adiciona gates.
5. **Evidência vem da máquina.** Teste, CI, mutação e diário provam; alegação do agente não conta.
6. **Núcleo puro, adaptadores finos.** Lógica em Node sem I/O (`gates/src`); mod, hooks clássicos e CLI são adaptadores. Nada crítico depende só da API de mods.
7. **Didático por padrão, silencioso por parâmetro.**

## 5. Arquitetura

```
pacote (schema do Gabarito) ─► /gabarito spec ─► spec.aprovada ─► loop ─► homolog ─► política de entrega ─► prod
                                                      │
                 diário events.jsonl (append-only) ◄───┴──► projeção determinística ─► instantâneo (≤1,5k tok) · painel · relatório
```

- **Diário** `.harness/entregas/<GM-n>/events.<sessao>.jsonl` (um arquivo por sessão; projeção junta por `(ts, sessao)`): append-only, versionado na branch, cadeia de hash, canários de segredo, só o adaptador escreve. Unidade de retomada = task. Vocabulário fechado inclui `task.*`, `review.veredito`, `decisao.sombra`, `producao.acesso`, `testes.afetados`, `ci.resultado`, `emenda.*`, `desvio`, `custo.medicao`. Todo achado e emenda leva `causa: regra_negocio | tecnica` (indicador do Horizon U5).
- **Projeção** única → três saídas: instantâneo (único que entra no contexto), painel (Pane), relatório markdown. ETA = mediana de duração por task aprovada; sem ≥ 3 medições mostra "sem dados".
- **Guarda** em camadas: `permissions.deny` gravado pelo onboarding no `.claude/settings.json` do repo (bloqueio absoluto: segredo, integridade do harness); hook único PreToolUse com matchers Bash + `Edit|Write` + MCP e filtro `if`; mod `tool.call` tipado quando disponível; hooks clássicos como fallback dos anéis críticos. O doctor diz qual camada está ativa.
- **Mod** (early-access, aceito [D]): Pane, AbovePrompt, toast; `tool.call`; pouso via `/clear` + `prompt.submit`. Revalidação de fatos a cada build no CI do plugin. **ADR-1 (exceção ao princípio 6, com cláusula de morte):** construir sobre API "may change without notice" porque sem mod não existe painel nem pouso; **morre** se dois builds consecutivos quebrarem fatos de M2 sem correção em 48 h, ou se S3 (E1) provar que `classic.*` não roda no login do dono — nesse caso E4 sai do roadmap e a guarda fica só em hooks clássicos + `permissions.deny`.
- **Gates** publicados como pacote versionado (`npx`), não vendorizados; `gates/lib/` comum (config, git, cli, datas); `harness.config.json` enxuto (chaves mortas removidas).

## 6. Decisões de produto [D, salvo marcação]

Cada decisão traz a alternativa rejeitada e o motivo.

### 6.1 (D1) Guarda: classificar e mostrar, não barrar
*Rejeitado:* deny por regex de comando (1.1.0) — 44/77 bypasses autodeclarados, FP em `rm -rf .next` e SQL local, FN em MCP e `vercel --prod` (M3). *Rejeitado:* `allow` explícito nas faixas livres — suprime o prompt nativo (M1).
Ambientes declarados no onboarding (`guarda.ambientes.{teste,homolog,prod}` com hosts, projetos, bancos, MCPs, variáveis; detecção automática sugerida). Três faixas por alvo:
- **livre** (local, teste): a guarda **não decide** (sem `allow`, sem `deny`); o fluxo nativo de permissão segue.
- **mostrar** (homolog; leitura e execução em prod): não decide, grava `producao.acesso`, aparece no painel e no log.
- **pedir** (`permissionDecision: ask` nativo, só ao orquestrador; subagent recebe `deny` por `agent_id`): escrita em prod **fora** da política de entrega e de `guarda.producao.permitidos`; segredo; integridade do harness. `permitidos` evita só o `ask` da guarda — o prompt nativo do Claude Code continua. **§6.5 define o que faz o loop *parar*** (financeiro, estrutural, não conseguiu), não o que pede confirmação. Config da guarda lida de `origin/HEAD` (muda só por merge revisado).
Escrita em prod coberta pela spec e pela política de entrega **passa e aparece**. Anel destrutivo (`rm -rf`, `DROP`, reset) deixa de bloquear em teste/homolog; vira evento. Fail-closed só em prod-escrita fora de política, segredo e integridade. Escape hatch `GABARITO_ALLOW_*` removido; nenhuma mensagem ensina bypass.

### 6.2 (D2) Política de entrega (por spec, default por projeto)
*Rejeitado:* perguntar no momento do deploy — vira babá; *rejeitado:* produção sempre manual — contradiz autonomia quando o produto permite contínua.
`continua` (CI verde em homolog + smoke → sobe), `janela` (agente agenda para a janela declarada), `sob_demanda` (entrega em homolog, abre PR de release e para). Se a spec exige prod e a política não é contínua, o agente pergunta a janela **na partida**. Mecanismos nativos: GitHub Environments com required reviewers e wait timer; feature flag / dark launch quando a spec marcar; rollback automático se o smoke pós-deploy falhar. Produção rebuildar imagem é débito: promover digest de homolog.

### 6.3 (D3) Emendas e desvios
*Rejeitado:* toda melhoria exige autorização — para o loop a cada descoberta; *rejeitado:* agente decide sozinho o que entra — spec deixa de ser contrato.
- **Desvio necessário:** sem ele um critério de aceite da spec falha. Faz, grava `desvio` com evidência, segue. Se toca arquivos fora do plano ou passa de ~20% do esforço estimado da task, vira emenda.
- **Descoberta fora da spec:** backlog com evidência; não implementa; não interrompe.
- **Spec inviável:** fato prova REQ errado → `emenda.proposta` (diff + fato + alternativa); congela só aquele REQ; continua tasks independentes; dono julga em lote na fronteira da task. Aprovada vira `spec.emendada`; revisor confere contra a spec emendada.
- **Enablers** (adaptar o repo ao padrão sênior: CI, flags, DB template) são levantados **na fase de spec** e entram como tasks numeradas com estimativa; cada um sai com "por quê" didático em `docs/aprendizados/`.
- Sombra arbitra a fronteira desvio × fora da spec. `desvio` e `emenda` sem `evidencia` são recusados pelo diário.

### 6.4 (D4) Piso de qualidade (tighten-only)
*Rejeitado:* gates escolhidos por spec sem piso — cada spec negociaria TDD; *rejeitado:* suíte inteira em todo estágio — redundância medida em M4.
TDD por task: RED válido (falha pelo motivo certo, evidência no diário) → GREEN → refactor; sem evidência `task.concluida` é recusada. Review adversarial com mutação executada no diff; nunca a mesma instância que implementou. CI verde na PR. Lint e typecheck sem erro; ratchet de cobertura, warnings e duplicação (só melhora); sem segredo no diff; conventional commits; `lint-staged`. Spec sem seção de testes reprovada pela conformidade. Prosa de racionalização ("provavelmente", "deveria funcionar") é advertência do revisor, não deny.

**Estágios de teste (cada teste num lugar só):**

| Momento | Roda | Onde |
|---|---|---|
| durante a task | só afetados pelo diff (`turbo --filter`, `vitest --changed`) | local |
| fim da task | suíte unit + integração 1× | local |
| PR | afetados + lint + typecheck, cache de build, `concurrency: cancel-in-progress` | CI |
| merge em main | suíte completa 1× + e2e | CI |
| fim da entrega | e2e + UI/UX (Playwright, regressão visual) em homolog | CI |
| nightly | carga, segurança, mutação ampla | CI agendado |

Falha → só o que falhou + dependentes. 2 rodadas vermelhas na mesma PR ⇒ para. Flaky vai à quarentena e vira achado. **Banco:** template migrado e com seed 1× por sessão; cada worker/subagent faz `CREATE DATABASE … TEMPLATE` e dropa ao fim; nunca `migrate` do zero em subagent. Dependabot fora dos gates pesados. Build 1× com artefato. Evidência: CI grava `ci.resultado` no diário.

### 6.5 (D5) Interrupção em três níveis
*Rejeitado:* um só canal de alerta — tudo vira ruído e o humano ignora; *rejeitado:* som — irrita em dois dias.
- **Informar** (task aprovada, pouso, CI verde): só log.
- **Atenção** (emenda aguardando, 2ª rodada de review, CI vermelho 1×): item amarelo fixo na faixa; loop **continua** nas tasks independentes; dono julga em lote.
- **Parar** (não conseguiu; impacto financeiro: serviço, plano, cobrança nova; impacto estrutural: infra criada ou removida, DNS, IAM, migration destrutiva em prod, apagar recurso ou backup, billing; CI vermelho 2×; teto de tokens): cabeçalho do painel em vermelho com motivo e ação; notificação do sistema; faixa vira botão. Sem som. **O orquestrador nunca para em silêncio.**

### 6.6 (D6) Sombra
*Rejeitado:* perguntar ao humano — babá; *rejeitado:* Sombra com o transcript do orquestrador — herda o viés; *rejeitado:* adotar `ai-memory` como dependência — daemon + SQLite + embeddings para problema que ele não resolve nativamente, 5k commits em 5 meses.
Agente conselheiro em Fable 5.1, contexto frio (spec aprovada + regra de negócio/glossário do pacote + pergunta; **sem** o transcript do orquestrador). Fluxo: orquestrador consulta `decisoes.jsonl` por chave da pergunta → se ausente, chama a Sombra → resposta vira `decisao.sombra {pergunta_hash, resposta, fontes}` → entra no instantâneo → nunca repergunta. Regras: Sombra **não muda a spec** (se a resposta exige, vira emenda); decisão nunca é apagada, só substituída; teto de consultas por entrega **[M]**; responde também "qual é a boa prática aqui?" com fato e fonte. **Fatos, não achismo (D, 2026-11-02):** toda `decisao.sombra` carrega `fontes[]` (seção do pacote/spec, doc oficial, código lido) **ou** `medicao` (spike só-leitura com número); o diário **recusa** decisão sem um dos dois. Pergunta de regra de negócio sem fonte no pacote/spec ⇒ a Sombra responde "não está na regra" e abre emenda — nunca inventa. Pergunta técnica ⇒ pode ler doc, ler o repo e rodar spike só-leitura antes de responder; spike com escrita ou acesso externo segue a guarda como qualquer agente. Custo entra no teto de consultas.

### 6.7 (D7) Pouso (handoff automático)
*Rejeitado:* confiar no auto-compact — resumo não determinístico, cache expira; *rejeitado:* pousar no meio da task — retomada incorreta.
Acima de X% nenhum despacho novo; em X%, espera `SubagentStop` de todos, roda **afetados** e exige veredito do revisor da task corrente, grava diário, gera instantâneo ≤ 1,5k tokens, `/clear` + reinjeta. Só na fronteira da task. X medido entre 40/50/60% **[M]**, default 50 [D]. Kill switch: `.harness/PAUSAR` + `/gabarito pausar`; retomar recomeça a task; nunca despausa sozinho. Nunca confiar no auto-compact.

### 6.8 (D8) Paralelismo
*Rejeitado:* dormência por padrão (GM-8) — contradiz "máximo de velocidade"; *rejeitado:* banco do zero por subagent — gargalo medido (M4).
**Dinâmico, nunca fixo (D, 2026-11-02):** `capacidade.mjs` mede a máquina **em toda sessão e durante o loop** (núcleos, carga, memória livre, disco, processos pesados) e calcula slots = f(máquina, custo por slot); o custo por slot (RAM, CPU, disco de um subagent + clone de banco) é a **fórmula calibrada** em S4 — o número de slots do MacBook do dono é um exemplo da fórmula, não um valor gravado. Máquina melhor ⇒ mais slots; pior ⇒ menos; carga sobe no meio do loop ⇒ despacho novo espera. Worktree por task; DB template por worktree; plano marca tasks independentes. Slot = 1 ⇒ fila, não dormência. Dormência só aguardando CI. Runner remoto como slot extra fica para depois (backlog "isolamento remoto").

### 6.9 (D9) Modelos (recomendação, não imposição)
*Rejeitado:* modelos fixos no plugin — dono não quer "marretado"; *rejeitado:* Fable em todo review — créditos esgotados no GM-7.
Perfil por papel com motivo em uma linha: orquestrador Opus 5.5; implementador **a medir** (Sonnet 5.5 `high` × Opus 5.5 `low`, métrica = custo por task aprovada) **[M]**; revisor de task Opus 5.5; revisor final e Sombra Fable 5.1; spike Opus; checagens scriptadas Haiku 5.5 (< 100k). Usuário troca no `harness.config.json`; doctor avisa abaixo do recomendado, não bloqueia. Travas: Sombra e revisor nunca na mesma instância que implementou.

### 6.10 (D10) UI (mod) — detalhes em memória `ui-painel-decisoes`
*Rejeitado:* avatares em pixel, identicon, monograma, glifo-por-papel; dashboard web; custo em dinheiro; emoji — todos recusados pelo dono em 2026-10-31; a comunidade premia texto minimal + barras (M6).
Tudo no CLI: Pane sempre aberto + faixa + toast. Direção: **árvore orquestrador→agentes + barra de plano**, texto monoespaçado, glifos `● ◐ ○ ✓ ✗`, barras `█░` com cor por limiar, nome do agente colorido (identidade), glifo colorido (estado). Sem emoji, sem dinheiro (tokens, limites 5h/7d, janela de contexto), sem siglas internas. Orquestrador em evidência no topo. Tasks ≠ agentes: task é linha da timeline, agente é chip na task; etapas RED/GREEN/refactor dentro da linha; fonte das tasks = plano da spec (checklist nativa pode estar vazia). Presets JSON: `esquadrao` (padrão) e `executivo` (só KPIs, vocabulário da visão executiva do Horizon); troca a quente. Temas de cor `color` e `mono`. Pacotes de nomes sorteados por sessão com âncoras líder/sábio: Terra Média, Heróis, Galáxia distante, Hogwarts; pacote próprio em `temas/nomes/<pacote>.json`. Densidade por largura (44/60/80+ colunas), nunca quebra linha. Narração didática desligável. **O painel não exibe log de ferramentas** (nenhum "Read arquivo X", "Bash …", chamada de MCP): tudo que aparece é evento do diário traduzido para linguagem natural — o que cada agente está fazendo em termos do trabalho ("escrevendo o teste que falha para o login"), estado das tasks, acesso a produção, decisões, interrupções. Detalhe cru (comandos, arquivos) existe no diário e sai só sob demanda (`/gabarito log --detalhe <agente>`). Área de resposta para `/gabarito …`; nativos via `MessageDisplay` **[M]**. Nível Parar idêntico nos dois presets.

### 6.11 (D11) Onboarding
*Rejeitado:* manter as 4 fases e ~20 perguntas da 1.1.0 — dono: "muito confuso e nada intuitivo".
≤ 5 perguntas em linguagem de pessoa, cada uma com "por que pergunto" e default pré-selecionado; prévia do que será criado; um comando; só o necessário para começar — o resto é descoberto no uso ou perguntado na primeira vez e registrado. Alvo concreto: deixar o repo com a esteira padrão (§6.4) e medir a distância com o doctor. Critério: pessoa de produto sem terminal no dia a dia termina sozinha em < 5 min **[M, hipótese — validar com 1 pessoa real]**. Hierarquia Iniciativa → Epic → PBI continua interna; o usuário descreve, o agente classifica e explica.

### 6.12 (D12) Processo do próprio plugin
*Rejeitado:* "0 achado, MINOR incluído" — GM-7/GM-8, 0 código (§1); *rejeitado:* MINOR sem destino — perde rastro; adotado "zero MINOR sem decisão".
Spec de entrega ≤ 1 página, ≤ 10 REQ. Review: BLOCKER/MAJOR bloqueiam, MINOR → backlog com dono; teto 2 rodadas; fecha por mutação executada; Fable só no review final. Spike só para premissa externa sem plano B. Ledger enxuto: estado, rulings, corte. Primeira entrega mergeia código em ≤ 1 semana ou o processo é revisto. Renomear "Workflow TRUE" → **Fluxo Gabarito** (39 ocorrências em 15 arquivos [V]) com checagem de texto no CI. Dogfooding: harness instalado neste repo.

## 7. Interface com o Horizon (e qualquer produtor de pacote)

- **(D13) Schema do pacote é do Gabarito** [D] (*rejeitado:* schema do Horizon, D-H120/121 — um consumidor, N produtores; mudança lá quebraria o loop aqui): `pacote/v1` (`pacote.schema.json` + markdown), versionado no plugin; Horizon exporta nele; dev pode escrever à mão. 8 itens (protótipo aprovado, exemplos Dado/Quando/Então, regras com caso passa/falha, contratos de dados, roteiro de smoke, fronteira do escopo, glossário, pendências) + `manifest.json` (`schema_versao, iniciativa, epic, ciclo, versao, hash_sha256, prototipo, itens[], checklist, origem`).
- **Mapeamento mecânico** pacote → spec: exemplos → testes congelados; regras → mutações do revisor; contratos → tipos/schemas; smoke → e2e em homolog; pendências → spikes T0; glossário → contexto da Sombra; fronteira → checker de emenda. `/gabarito spec --pacote <dir>` gera o rascunho; humano assina.
- **Eventos de volta só via git** (`docs/pacotes/<EPIC>/v<n>/eventos.jsonl` ou check run): `spec.aprovada`, `homolog`, `producao`, `emenda`, `devolucao`. Nenhuma API entre os dois; preserva ADR-HZN-2.
- Pré-requisitos no Horizon (fora deste repo): reabrir D-H120/121; remover `alvo-de-teste.ts` → harness; "zero achado" → "zero bloqueante"; trilha curta para Epic P; emenda de pacote barata.

## 8. Abertos e a medir (bloqueiam requisito, não a visão)

| # | Item | Como fecha |
