## 3. Requisitos **(b)**

Notação: **[O]** vale para orquestrador, **[S]** para subagente, **[O,S]** para ambos. "Segmento" = trecho do comando separado por `|`, `&&`, `||`, `;`, `&` ou quebra de linha, depois do strip de REQ-H0-5; `2>&1`, `>&2`, `&>`, `>&` não separam.

### H0 — payload, raízes, composição (`_common.sh`)
- **REQ-H0-1** `gabarito_read_payload` extrai `tool_name`, `agent_id`, `agent_type`, `permission_mode`, `cwd`, `command`, `file_path`, `notebook_path`, `path`, `pattern`, `glob`, `url` e o `tool_input` serializado. `gabarito_read_command` vira casca sobre ela; R2/R3/R20 sem mudança de comportamento para O.
- **REQ-H0-2 (ilegível)** = stdin não é JSON, ou falta `tool_name`, ou falta `tool_input`. R2/R3/R20 isolados: fail-open declarado (como hoje). H2, H3, H4, H7: **deny**. A cadeia do matcher `Bash` passa a ser fail-closed para ilegível.
- **REQ-H0-3 (S)** S = `agent_id` não vazio. Fallback (só se M-B = não): `cwd` sob `*/.claude/worktrees/agent-*` ⇒ S; a negação diz "tratado como subagente pelo cwd". O fallback não é falsificável para o lado perigoso (S→O exigiria o Claude Code omitir `agent_id`); sessão do usuário aberta dentro de `agent-*` vira S (aceito, README).
- **REQ-H0-4 (raízes)** `RAIZ_WT` = `git -C <cwd> rev-parse --show-toplevel`; `RAIZ_PRINCIPAL` = diretório pai de `git -C <cwd> rev-parse --path-format=absolute --git-common-dir`. Fora de git: ambas = `cwd`. Todo alvo "`<raiz>/…`" desta spec vale para **as duas** raízes. Caminhos comparados após expandir `~` e `$HOME` e resolver `.`/`..` (sem seguir symlink do alvo final, que pode não existir).
- **REQ-H0-5 (strip)** Antes de segmentar e varrer, remove-se: (i) corpo de heredoc com terminador **citado** que só escreve arquivo (`cat >`/`cat >>`/`tee [-a]`), como `_common.sh:161-178`; (ii) para H3 e para a regra de `claude` de REQ-H4-3b, a string de `git commit -m` e de `gh … --title|--body` **sem** `$(`, crase, `${`, `<(`. `-F|--file|--body-file <caminho>` é leitura do caminho, nunca string. H3/H4/H7 **não** usam `gabarito_scan_text` (que apaga `echo|printf|grep|sed`).
- **REQ-H0-6 (composição)** Entre hooks do mesmo evento: deny > ask > allow (regra do Claude Code). Hatch de R2/R3/R20 (exit 0 + systemMessage) não anula deny/ask de outro hook. Hook do plugin que falha por erro próprio sai com 2 + deny, nunca com outro código (exit ≠ 0 e ≠ 2 é erro não bloqueante no Claude Code).
- **REQ-H0-7 (decisão do O quando `ask` não chega)** Para cada ferramenta em que M-A medir que o `ask` **não** chega em auto mode: decisão do O = **deny** quando `permission_mode = auto` e **ask** nos demais modos, com mensagem "rode fora do auto mode ou peça ao usuário `! <comando>`". Exceção única: REQ-H4-3b (`onboarding-config.mjs` vindo de O ⇒ allow, a skill já pede o ok). Ferramenta medida "chega" ⇒ ask em todos os modos.

### H2 — MCP e WebFetch em produção (`guard-mcp.sh`, matcher `mcp__.*|WebFetch`)
- **REQ-H2-1 (gatilho de produção)** Vale se qualquer um: (a) servidor (entre `mcp__` e o próximo `__`) ∈ `producao.mcp.servidores`; (b) o `tool_input` serializado contém item de `producao.identificadores`; (c) valor de **campo de conexão** casa o ERE de host/URL de produção da R3 ou `GABARITO_PROD_PATTERNS_EXTRA`. Campo de conexão = chave, em qualquer nível, cujo **token** (separado por `_`, `-` ou fronteira camelCase, comparado em minúsculas) é `url|uri|host|hostname|endpoint|project|projectid|ref|dsn|conn|connection|database|db|command|domain`, e `query|sql` só quando o nome da ferramenta contém o token `sql` ou `execute`. Para `WebFetch`, o campo é `url`.
- **REQ-H2-2 (segredo via MCP)** Nome da ferramenta (após o servidor) com **substring** `env|secret|token|credential|key`, ou igual a `get_edge_function`, ⇒ gatilho de segredo. Falso positivo aceito: `list_project_custom_environments`.
- **REQ-H2-3 (leitura)** Ferramenta de leitura = nome com token `get|list|search|read|query|find|fetch|count|aggregate|describe|filter|analyze|generate|export|download|check|status|preview|resolve|lookup|whoami|health|navigate|open|view|load|browse|screenshot|snapshot`, ou `execute_sql`; `WebFetch` é leitura.
- **REQ-H2-4 (decisão)** Gatilho (a)/(b)/(c): S ⇒ deny; O + leitura ⇒ ask (via REQ-H0-7); O + não-leitura ⇒ deny. Só gatilho de segredo: S ⇒ deny; O ⇒ ask. `execute_sql` ⇒ ask com "aprovar = autorizar o SQL exibido, inclusive se escrever". Sem gatilho: S segue para REQ-H7-4; O ⇒ allow.
- **REQ-H2-5 (config)** `harness.config.json` ganha, opcionais: `producao.mcp.servidores: string[]`, `producao.identificadores: string[]`. Sem as duas chaves, stderr a cada chamada MCP de O: "producao.* ausente — prod só detectada por padrão de host". `gabarito-instalar` pergunta; doctor avisa (não reprova).

### H3 — segredos [O,S] (`guard-secrets.sh`, matcher `Bash|Monitor|Read|Grep|Glob|NotebookEdit`)
Contra exibição **acidental** (D9). Para S, H7 já recusa a classe de disfarce; H3 cobre o que a lista branca de S permite (ex.: `cat`).
- **REQ-H3-1 (menção a `.env`)** Menção = ERE `(^|[[:space:]/'"=<>(|;&:@,{])\.env([.][A-Za-z0-9_.-]*)?($|[[:space:]'"|;&)<>*?{},$\[])`. Todo segmento com menção, fora de REQ-H3-4 (exceções) e de REQ-H3-2 (formas permitidas) ⇒ **deny**, qualquer que seja o comando.
- **REQ-H3-2 (formas permitidas com menção)** (i) loader: `dotenv … -e`, `--env-file[= ]`, `git check-ignore`, `test -e|-f`, `[ -e|-f … ]`; (ii) primeiro token do segmento ∈ `touch|ls|stat|git ls-files|git rm --cached`, sem `$(`, crase, `<(`, `-exec|-execdir|-ok|-okdir`, e o segmento **não** é seguido de `|` (`ls .env* | wc -l` ⇒ deny, aceito); (iii) `cp|mv|git mv` com **origem** sob exceção de REQ-H3-4 e destino `.env*` (`cp .env.example .env`); `git add` só se **todo** operando `.env*` está sob exceção de REQ-H3-4 e sem `-f|--force|-N|--intent-to-add`; (iv) `--exclude=`/`--exclude-dir=` como argumento; (v) `echo|printf` de literal **sem `$`** com `>>` para `.gitignore|.dockerignore`.
- **REQ-H3-3 (exibir sem menção a `.env`)** ⇒ deny: `gcloud secrets versions access`; `gcloud auth print-access-token|print-identity-token`; `gh auth token`; `security find-*-password … -w`; `printenv`, `env`, `set`, `export -p`, `declare -p`, `typeset -p`, `compgen -v`, `env -0` sem argumento; `printenv|env … <NOME>`; `declare|typeset|export -p <NOME>`; `echo|printf` (inclusive `/bin/echo`, `builtin`, `command`) com `$<NOME>`/`${<NOME>…}`; here-string ou heredoc **sem** aspas com `$<NOME>`; `X=$<NOME>` seguido de `$X` em `echo|printf` no mesmo comando; `ENVIRON[` com `<NOME>` ou `for … in ENVIRON`; `ps -E|e|eww`; `launchctl getenv`; `jq` com `$ENV` ou `env.`. `<NOME>` = `[A-Za-z0-9_]*(KEY|SECRET|TOKEN|PASSWORD|PASSWD|CREDENTIAL|SERVICE_ROLE|DATABASE_URL|DSN)[A-Za-z0-9_]*`.
- **REQ-H3-4 (exceções)** Sufixo `.example|.sample|.template|.dist` sempre permitido. `segredos.permitidos: string[]` (nomes de arquivo, ex.: `.env.staging`) libera **só [O]**.
- **REQ-H3-5 (uso por expansão)** `$<NOME>`, `${<NOME>}`, `process.env.<NOME>` fora de REQ-H3-3: [O] allow (`psql "$DATABASE_URL"`); [S] já negado por REQ-H7-1 (`$` fora de aspas simples).
- **REQ-H3-6 (arquivos)** `Read`/`NotebookEdit`/`Grep`(`path`, `glob`)/`Glob`(`path`, `pattern`) sobre `.env*` fora de REQ-H3-4, `*.pem|*.key|*.p12|*.pfx`, ou caminho de credencial — `~/.config/gcloud/`, `~/.config/gh/`, `~/.netrc`, `~/.npmrc`, `~/.ssh/`, `~/.aws/`, `~/.docker/config.json`, `~/.claude/.credentials.json`, `~/.claude.json`, `~/.supabase/access-token`, `~/.zshrc`, `~/.zprofile`, `~/.bash_profile`, `~/.bashrc` — ⇒ deny. Para `Glob.pattern`/`Grep.glob`: deny se o padrão pode casar `.env` (contém `.env`, `.en*`, `.e*`, `.*`, `**/.*`).
- **REQ-H3-7 (mensagem)** "Agente nunca exibe segredo. Para usar o valor, carregue sem exibir (`dotenv -e .env -- <cmd>`, `--env-file`); para ver, peça ao usuário `! <comando>` (ex.: `! cat .env`)."

### H7 — subagente em lista branca (`guard-subagente.sh`, matcher `.*`; só age com payload de S)
- **REQ-H7-1 (recusa estrutural)** [S] comando em `tool_input.command` (`Bash`, `Monitor`, outra) ⇒ deny se contém, **fora de aspas simples**: `$`, crase, `\`; **fora de qualquer aspas**: `*`, `?`, `[`, `{`, `~`; em qualquer posição: `$(`, `<(`, `>(`, `<<<`, heredoc com terminador **não** citado, `GABARITO_ALLOW_`; palavra com aspas coladas a caracteres sem aspas (`.'env'`, `a"b"`); `eval`, `exec`, `source`, `.` como comando; interpretador com script por stdin (`-` como script, `<` como fonte, `sh -s`). Glob literal entre aspas duplas (`npx jest -t "cria.*pedido"`) passa.
- **REQ-H7-2 (lista)** Todo segmento precisa casar um item (token inicial + restrições) ou um prefixo de `subagente.comandos`; senão deny.
  - `git` {`status`, `log`, `show`, `diff`, `blame`, `rev-parse`, `ls-files`, `merge-base`, `branch` só listagem (sem `-d|-D|-m|-M|-f|--delete|--move|--force`), `add` com caminhos nomeados (sem `-A|.|--all|-f|-N|-u|-p`), `commit -m` (sem `-a|-F|--amend`), `switch|checkout -b|-c`, `restore` e `checkout --` com caminhos nomeados (desfaz mutação do revisor), `stash list`, `worktree list`, `grep` sem `--untracked|--no-index|-O`}; recusa global `-c`, `--config-env`, `--output`, `--exec-path`, `--git-dir`, `--work-tree`; `-C` só com subcomando listado; nunca `push`.
  - `gh` só {`pr view|list|checks|diff|status`, `run list|view`, `auth status`}.
  - Texto/arquivo: `ls`, `pwd`, `cat`, `head`, `tail`, `wc`, `sort` (sem `-o`), `uniq` (1 entrada), `cut`, `diff`, `cmp`, `jq` (sem `--rawfile|--slurpfile`, sem `$ENV`/`env`/`input_filename` no programa), `echo`, `printf`, `date` (sem `-f`), `which`, `mkdir`, `touch`, `cp`, `mv`, `test`, `[`, `true`, `cd` (destino no escopo de REQ-H7-3).
  - `grep`/`rg`/`egrep`: recursivo só se **todo** caminho é subdiretório nomeado no escopo (nunca `.`, `./`, `..`, raiz, ausente).
  - `find` só com `-name|-iname|-path|-type|-maxdepth|-mindepth|-newer|-print`.
  - `sed -n '<N>[,<M>]p' <arquivo>`.
  - Runners: `npm test`, `npm run <lint|build|test|test:*|typecheck|format|format:check>`, `npm ci`; `npx` {`jest`, `vitest`, `tsc`, `eslint`, `prettier`, `playwright test`} sem `-p|--package|-c|--call|--yes|-y`; `node --test <caminhos>`; `node <arquivo>.(mjs|js|cjs)` e `bash <arquivo>.sh` com arquivo no escopo de REQ-H7-3; `python3 -m pytest`, `pytest`.

Item que contém `rm`, `sudo`, interpretador com `-e|-c` ou `GABARITO_ALLOW_` é ignorado com aviso em stderr.
- **REQ-H7-3 (escopo de caminho)** Para Bash/Monitor (operandos e destinos de `>`, `>>`, `tee`, `cp`, `mv`, `touch`, `mkdir`, `cd`) e para `Read|Grep|Glob|Write|Edit|NotebookEdit`: caminho precisa estar sob `RAIZ_WT`, `RAIZ_PRINCIPAL`, `$TMPDIR`, `/tmp` ou `/private/tmp`; leitura (`Read|Grep|Glob`, `cat`, `head`, `tail`, `wc`, `diff`) também sob `~/.claude/plugins/` (referência do plugin). ## 5. Limites declarados (G9)
1. Grep, não sandbox: arquivo escrito e depois executado (script, `package.json`, config de teste) não é inspecionado. Para S é o **único** caminho restante (`node <arquivo>`, `npm run test`); barreira = escopo do brief + review.
2. O com disfarce deliberado (`.'env'`, `$(…)`, interpretador inline, glob) não é visto por H3 — D9: O não é adversário.
3. O: exibição indireta de segredo usado (`curl -d "$TOKEN" <eco>`, `${TOKEN:0:8}`).
4. O: leitura em massa sem o literal `.env` (`find . -type f | xargs cat`, `tar czf a.tgz .`). Para S, `xargs` e `tar` não estão na lista.
5. S sem `agent_id` e fora de `agent-*` ⇒ tratado como O (M-B).
6. deny > ask > allow é regra do Claude Code; o teste `runAll` mede só a cadeia do plugin.
7. `producao.*` ausente ⇒ MCP de prod só detectado por padrão de host (REQ-H2-5).
