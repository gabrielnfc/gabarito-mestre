### H3 — segredos (`guard-secrets.sh`, matcher `Bash|Monitor|Read|Grep|Glob|NotebookEdit`)
Port do `guard-secrets.mjs` do True Force, em bash com o parser de `_common.sh`.
- **REQ-H3-1 (exibir — O e S ⇒ deny, sem hatch)** _(Emenda r2, review r1 B3: lista fechada de comandos deixava `cp .env.local /tmp/a`, `curl -F f=@.env`, `tar .env` passarem)_ **Regra-mãe, como `guard-secrets.mjs:56-58`:** o comando é dividido em segmentos (`|`, `&&`, `||`, `;`, `&`, quebra de linha); **todo segmento que menciona `.env*`** — menção = ERE `(^|[[:space:]/'"=<>(|;&:@,{])\.env([.][A-Za-z0-9_.-]*)?($|[[:space:]'"|;&)<>*?{},])` (prefixo inclui `@` de `curl -F f=@.env`; sufixo inclui glob `*?{`; r3, review r2 m15) — fora das exceções de H3-5 e que não casa H3-2 (loader) ⇒ deny, qualquer que seja o comando. Os itens abaixo são casos adicionais (sem `.env` no texto) e exemplos. Bash/Monitor: `gcloud secrets versions access`; `security find-*-password … -w`; `printenv`/`env`/`set`/`export -p`/`declare -p`/`compgen -v` sem argumento; `printenv|env … <NOME_DE_SEGREDO>`; `echo`/`printf` com `$…<NOME_DE_SEGREDO>`; `cat|head|tail|less|more|bat|grep|rg|sed|awk|cut|strings|xxd|base64|source|.` sobre `.env*`; `git show …:.env*`; `git diff|log -p … -- .env*`; redirecionamento `< .env*`; `env -0`; `typeset -p`; `ps -E|eww`; `launchctl getenv`; `jq` com `$ENV`/`env`; `gh auth token`; `gcloud auth print-access-token|print-identity-token`; here-string ou heredoc **sem** aspas contendo `$NOME_DE_SEGREDO`; `echo`/`printf` invocados por caminho (`/bin/echo`) ou via `builtin`/`command`; `X=$NOME_DE_SEGREDO` seguido de exibição de `$X` no mesmo comando. Disfarces cobertos: `c\at .env`, `cat -- .env`, `.env?`/`.env*`; e glob que **pode** casar `.env` sem o literal — ERE `(^|[[:space:]/'"=<>(|;&:@,{])\.((e|en|\{?env)?[*?]|\{[^}]*env|\[[^]]*\])` (`.e*`, `.en*`, `.*`, `.{env,bak}`, `.[e]nv`) ⇒ tratado como menção (r5, review r4 m21) (r4, review r3 m19; a origem também não via) _(Emenda r1, review r0 M1/m2)_. NOME_DE_SEGREDO = `[A-Za-z0-9_]*(KEY|SECRET|TOKEN|PASSWORD|PASSWD|CREDENTIAL|SERVICE_ROLE|DATABASE_URL|DSN)[A-Za-z0-9_]*`.
- **REQ-H3-2 (loader e formas só-de-nome — permitido)** `dotenv -e`, `--env-file=`, `git check-ignore`, `test -f`/`[ -f ]` sobre `.env*` ⇒ allow. _(Emenda r3, review r2 M10: a regra-mãe negava `cp .env.example .env`, `echo ".env.local" >> .gitignore`, `git commit -m "…​.env…"`)_ Também allow, porque o **conteúdo** não sai: (i) `.env*` como **destino** de `cp|mv` cuja **origem** é exceção de H3-5 (`cp .env.example .env`); (ii) argumento de `touch|ls|stat|find -name|git add|git rm|git ls-files|rm` (`ls -la .env*` lista nomes; `rm` segue sob R2) — **só quando** esse comando é o **primeiro token do segmento**, o segmento **não** contém `$(`, crase, `<(`, `-exec|-execdir|-ok|-okdir`, e **não é seguido de `|`** (saída não entra em pipe; `ls .env* | wc -l` fica deny — aceito); `git mv` só com destino `.env*` _(r4, review r3 M11a)_; (iii) `--exclude=`/`--exclude-dir=`, e `echo|printf` com **literal sem `$`** acrescentado por `>>` a `.gitignore|.dockerignore` (r4, M11b); (iv) dentro da string de `git commit -m`, `gh … --title|--body` e de heredoc com terminador citado que só escreve arquivo — **só essas strings**, e **só se não contêm `$(`, crase, `${`, `<(`** (mesma regra do heredoc citado em `_common.sh`), são removidas antes da varredura; `-F|--file|--body-file <caminho>` é **leitura** do caminho, nunca string (r4, M11c); `echo`/`printf`/`grep`/`sed` continuam varridos. **Segue deny (exfil):** `cp .env.local <qualquer>` (origem não é exceção), `curl -F f=@.env*`, `tar|zip|rsync .env*`, `vercel env pull` e qualquer comando que **leia** o arquivo.
- **REQ-H3-3 (uso por expansão)** `$NOME_DE_SEGREDO` / `${…}` / `process.env.NOME_DE_SEGREDO` fora de REQ-H3-1: O ⇒ allow (uso — `psql "$DATABASE_URL"`, `legitimos.txt:41`); S ⇒ deny. **Limite declarado (§5):** exibição indireta pelo O (`curl -d "$TOKEN" <eco>`, `${TOKEN:0:8}`) não é vista — dever do O, não gate.
- **REQ-H3-4 (arquivos)** `Read`/`NotebookEdit` em `.env*`, `*.pem|key|p12|pfx`, ou caminho de credencial (`~/.config/gcloud/`, `~/.config/gh/`, `~/.netrc`, `~/.npmrc`, `~/.ssh/`, `~/.aws/`, `~/.docker/config.json`, `~/.claude/.credentials.json`, `~/.claude.json`, `~/.supabase/access-token`, `~/.zshrc`, `~/.zprofile`, `~/.bash_profile`, `~/.bashrc`) ⇒ deny O e S. `Grep` com `path` ou `glob`, e `Glob` com `path` ou **`pattern`**, apontando para esses ⇒ deny _(r1: o campo do Glob é `pattern`)_. **Limite declarado:** `Grep pattern=KEY path=<raiz>` lê `.env.*` não ignorado pelo git — para S, `Grep` sem `path` ou com `path` = raiz ⇒ **deny sempre** _(r2, review r1 m13: monorepo tem `apps/*/.env.local`)_; para O fica como dever.
