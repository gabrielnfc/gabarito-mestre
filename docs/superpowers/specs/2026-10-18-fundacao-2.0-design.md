Toda afirmação sobre o mod é **(b)** até o plano ser executado e a T0 medir. Fatos M1–M7, M11, M14–M22 são **(a)** (lidos ou medidos pelo dono ou por esta sessão, com linha). **M8, M9, M10, M12, M13, M23, M24 são alegações** — leitura de README/paper/issue/relatório de subagente (R18), marcadas assim na tabela; nenhuma delas é racional único de ADR sem T0 que a reproduza.

Escopo: a fundação sobre a qual o loop autônomo (GM-9) será construído e medido — (1) diário de bordo append-only com projeção determinística, (2) guarda de `tool.call` tipada que substitui a guarda Bash de destrutivos como camada primária, (3) pouso (handoff automatizado na fronteira da task) com kill switch, (4) linha de status mínima. **Sem loop autônomo:** o dono continua orquestrando; o que muda é que ele passa a ter guarda tipada, diário, retomada determinística e handoff automático. O método passa a se chamar **Fluxo Gabarito** (D2); a renomeação nos artefatos publicados é GM-13 (Fora de escopo).

Convenções desta spec: **O** = orquestrador (loop principal, `e.agentId === undefined`); **S** = subagente (`e.agentId` definido); **humano presente** = `$.session.surfaces()` não vazio (terminal, desktop, vscode ou mobile — M19; vazio em `-p` puro, M4); **origem humana** = `origin.kind ∈ {composer, bridge}` — qualquer outro `kind` da união aberta `PromptOrigin` (M19) **não** é humano; **leitura** = `tool ∈ {Read, Glob, Grep}` ou Bash cujo comando efetivo está na lista só-leitura de REQ-H7-3 (GM-7:119) e sem redirecionamento de escrita. Ponteiros para a spec arquivada do GM-7: `git show archive/GM-7:docs/superpowers/specs/2026-10-15-hotfix-1.1.1-design.md` (abreviado **GM-7:**`<linha>`).

- **D5 — Diário.** Journal append-only por entrega, em git, só o mod escreve (via CLI, ADR-ARQ-2; protegido por anel de integridade, ADR-GRD-3); unidade de retomada = task; arquivo por entrega **e por sessão**, dono em cada evento. *Rejeitado:* ledger markdown editado pelo modelo (frágil para reconstruir); estado só no `$.store` (não cruza máquina, não é auditável); arquivo único com lock (M15: o mod não tem lock; e exigia dois layouts — achado M17 da rodada 1).
- **D6 — Pouso.** Handoff automatizado na fronteira da task; X% é variável de custo medida, não limiar fixo; nunca confiar no auto-compact a 100%. *Rejeitado:* 60% fixo; compactar no meio da task.
- **D7 — Kill switch (ajustada 2026-10-19, R7).** Pausar interrompe o turno principal (`$.turn.abort`, único mecanismo da API — M4), nega todo `tool.call` de S e todo `agent.spawn` enquanto pausado; retomar recomeça a task do início; só origem humana despausa. *Rejeitado:* pausa suave deixando subagentes terminarem; "matar cada subagente" (não existe `$.agent.kill` — M4; o que acontece com o processo de um subagente em background é a T0-4, mas ele não escreve mais nada: GRD-14).
- **D8 — Hatch.** Autorização de produção/destrutivo só por origem humana (`/gabarito autorizar` ou botão), para o **hash do último comando negado**, uma vez; nunca no texto do comando. *Rejeitado:* manter `GABARITO_ALLOW_*` no comando (M7: autodeclarável); autorização por anel (o modelo trocaria o comando autorizado por outro do mesmo anel — achado M8 da rodada 1).

## ADRs

- **ADR-ARQ-1 — Adaptador único sobre `$` com portas injetáveis.** Só `hooks/mod/adaptador.ts` chama a API de mods; guarda, pouso e projeção são funções puras que recebem as portas `Diario` (produção: CLI via `$.process.run`; teste: diário em memória sobre `mock.store` — M17) e `Pouso {mcp, command, prompt, fs}` (produção: `$.mcp.call`, `$.command.run`, `$.prompt.submit`, `$.fs`; teste: fakes — o kit não tem mock de `mcp`/`process`/`fs`, M17). Racional: API "may change between releases without notice" (README oficial); `plugin test` não tem fs/process/rede. *Rejeitado:* chamar `$` direto nos módulos (cada mudança da API toca tudo; testes impossíveis sem fs). Cláusula de morte: quando a API for declarada estável, o adaptador pode ser inlined; as portas ficam.
- **ADR-ARQ-2 — Núcleo do diário puro em `gates/src/diario/`; I/O do journal só no CLI.** Núcleo (`canonical`, `hash` via `crypto.subtle`, `verify`, `project`, `instantaneo`, `receipt`, `formataStatus`, `detectaPluginAcima`) sem `node:*` — importável pelo mod (M15) e pelo CLI. Append com `fsync`, criação `wx` e leitura de diretório vivem em `gates/scripts/diario.mjs` (Node), invocado pelo mod por `$.process.run(["node", "<root>/gates/scripts/diario.mjs", …])` sem shell, com timeout explícito. Arquivos que **não** são journal (`.harness/mod-ativo.<sessao>`, `.harness/PAUSAR`, `.harness/.gitignore`) o mod escreve por `$.fs.write`. Racional: o instalador já copia `gates/` para `tools/gabarito-gates/` do projeto — o CI do dev verifica o diário sem mod; o módulo de hooks não tem Node (M15). *Rejeitado:* clonar o ECC inteiro dentro do mod (M8 usa `node:crypto`/`node:fs`; não carrega — achado M1 da rodada 1); diário dentro de `hooks/mod/` (CI do dev sem mod não verificaria). Condição: T0-2 confirma que o núcleo compila sem `node:` e que o append por `$.process.run` cabe no orçamento; senão o núcleo é duplicado por script com igualdade verificada no CI.
- **ADR-ARQ-3 — Fora de projeto harness (D14).** Sem `harness.config.json` na raiz git ⇒ modo "sem harness" (REQ-CFG-2). Sem cláusula de morte.
- **ADR-GRD-1 — Fail-closed com mecanismo.** Config de `guarda`/`diario` ausente num projeto harness, diário inválido ou erro interno da guarda ⇒ `deny`. Mecanismo: (i) toda registration de `tool.call` e `agent.spawn` carrega `.catch(($, e, next) => next.called ? next(e) : { deny })` (M16: sem isso hook falho = ferramenta roda); (ii) registrations de `turn.start|complete` e `session.*` — cujo retorno não tem efeito (M4) — carregam `.catch` que grava `$.state.guardaFalhou = {evento, ts}`, e o próximo `tool.call` nega tudo exceto leitura até `/gabarito retomar` (REQ-GRD-12); (iii) nenhuma leitura do journal no caminho de `tool.call` — a guarda lê projeção e estado git cacheados em `$.state` (preenchidos em `turn.start`); o único I/O permitido no `tool.call` é **um** `$.fs.stat({resolve:true})` do anel de integridade (M15: deny-list por grafia é best effort). *Rejeitado:* "allow with warning" do gateguard (exigiu corpus de 184 passos para alegar 0 bypass, M9); `verify` do journal dentro do `tool.call` (estoura os 10 s do budget e vira fail-open — achado B2 da rodada 1). Sem cláusula de morte.
- **ADR-GRD-2 — `guard-destructive.sh` desligado só na sessão com guarda tipada provadamente ativa.** O `.sh` sai 0 quando existe `.harness/mod-ativo.<session_id>` (o `session_id` vem do JSON que o hook clássico recebe no stdin, M6) **e** seu `ts` tem menos de 60 s (renovado a cada 20 s por `$.clock.every`; cortes iniciais, T0-5 calibra, REQ-GRD-10); o arquivo só nasce depois de `guarda.pronta` — gravada em `$.store` por `/gabarito ativar-guarda` (origem humana), que roda o corpus REQ-GRD-11 pelo adaptador real; a suíte de `plugin test` não grava o `$.store` real (M17). `guard-production.sh` e `guard-versioning.sh` nunca desligam (D4). *Rejeitado:* marcador sem validade (persiste após crash/unload = fail-open — achado M13 da rodada 1); marcador por repositório (2ª sessão sem o mod no mesmo repo veria marcador fresco — achado M-i da rodada 2); marcador no carregamento do mod (janela sem guarda durante o dogfooding — achado B4); `guardaPronta` gravado pela suíte (`mock.store` em memória — achado B1 da rodada 2). Cláusula de morte: ao fim da A1, se T0-9 mostrar o mod ≥ Bash no corpus, `guard-destructive.sh` é removido em GM-14.
- **ADR-GRD-3 — Anel de integridade (D13).** `deny` [O,S] a qualquer ferramenta cujo caminho (resolvido por um `$.fs.stat({resolve:true})`) ou texto de Bash toque os alvos de REQ-GRD-13, ou invoque `diario.mjs`/`claude plugin|config|mcp`. Anéis produção, segredo e integridade avaliam o **texto cru** antes de qualquer desembrulho e nunca são fail-open (REQ-GRD-7 só vale para destrutivo e escopo). Disfarce deliberado de O (glob `rm .ha*/PAUSAR`, interpretador inline `python -c …`, symlink criado no mesmo comando) é **limite declarado (G9, R7 GM-7:141)**: o que um agente escreve por acidente é coberto; composição deliberada de O é registrada como `guarda.limite` quando detectável e fica fora do corpus de bypass; para S, interpretadores e symlinks já caem na lista branca. Reparo e unlock só por `/gabarito reparar` de origem humana (REQ-DIA-12). Sem cláusula de morte.
- **ADR-POU-1 — Pouso = `/clear` + injeção, disparado fora do hook, concluído pelo próprio callback.** `turn.complete` só marca estado; um `$.clock.after(0, fn)` (callback que o turno não espera) chama `$.command.run({command:"clear"})` e depois `$.prompt.submit({text:"retome"})`; como `session.start` **nunca** dispara em `/clear` e `session.end` dispara (M4), é o próprio callback que grava `sessao.retomada`, guarda o instantâneo em `$.state.instantaneo` e deixa `prompt.compose` injetá-lo (REQ-POU-6). Racional: M3 — `session.compact` não roda em org gerenciada; M4 — `$.command.run` rejeita dentro de hook que o turno espera e `$.session.compact` rejeita enquanto um turno roda. `$.session.compact({instructions})` é otimização opcional quando `pouso.usarCompact` e o hook está disponível. Limite declarado (G9): `clock.after` é um dispatch que um plugin acima pode recusar (M4) — nesse caso o pouso não acontece e a status mostra "pouso recusado por <plugin>" lido de `next.trace`. *Rejeitado:* chamar `/clear` dentro de `turn.complete` (rejeita, M4); confiar no `session.compact` (M3); retomar estado em `session.start` após o pouso (não dispara — achado B3 da rodada 2). Cláusula de morte: se a Anthropic liberar o hook para plugins de usuário e a T0-3 mostrar paridade, inverter o padrão.
- **ADR-DIA-1 — Evento recusado, nunca redigido.** Canário de segredo ⇒ append falha; o chamador corrige. Racional: diário vai para `main`; redação silenciosa esconde o bug que gerou o vazamento. *Rejeitado:* redigir e gravar (flightdeck) — esconde a origem. Sem cláusula de morte.

O estimador é local (chars/3,5 calibrado uma vez por `count_tokens` na T0-6) — o teste do `gates/` não usa rede.

Durante o rollout 2–4 (sem mod carregado) o dono emite `spec.aprovada` pelo CLI à mão — declarado como limite (G9) e visível no evento (`agente:"cli-manual"`).

Nenhum outro caminho emite eventos de task.

### GRD — guarda de `tool.call`

- **REQ-GRD-1** Given qualquer `tool.call` When a cadeia de regras avalia Then o veredito é `deny` ou `allow`; `stricter(chain, verdict)` nunca devolve veredito mais permissivo que o anterior (deny → allow é impossível); `rewrite` (`next({...e, args})`) não é emitido na A1. Ordem fixa dos anéis: integridade → produção → segredo (os três sobre o texto cru) → destrutivo → escopo (após desembrulho).
- **REQ-GRD-2** Given `e.agentId === undefined` When a guarda avalia Then o chamador é O: lista negra contra acidente (R7, GM-7:141). Given `e.agentId` definido Then é S: lista branca de comandos Bash = REQ-H7-3 da GM-7 (GM-7:119) + `subagente.comandos` da config; tudo fora dela ⇒ `deny`. Teste: mesmo comando, dois vereditos.
- **REQ-GRD-3 (anel produção)** Given comando, caminho, URL, variável ou ferramenta com host/credencial de produção (regras de `guard-production.sh` portadas), ou push/merge para branch protegida — `git push` com refspec para `main|prod*`, `git push --force*`, `gh pr merge`, `git merge` com `$.state.git.branch ∈ main|prod*`, `git push` sem refspec com `$.state.git.upstream ∈ main|prod*` **ou desconhecido** (fail-closed) — ou ferramenta `mcp__<servidor>__*` com servidor em `guarda.mcpProducao` When a guarda avalia Then `deny` para O e S, sem hatch no texto (D8). `$.state.git = {branch, upstream}` é lido por `$.process.run(["git","rev-parse",…])` em `turn.start` (I/O fora do `tool.call`, ADR-GRD-1). Corpus: `producao.txt` + casos tipados (`mcp__supabase__execute_sql` com projeto em `mcpProducao`; `gh pr merge`; push sem refspec com upstream desconhecido).
- **REQ-GRD-4 (anel destrutivo)** Given Bash classificado destrutivo (classificador da T0-17 + listas GM-7:39–40: `rm` em qualquer forma, `git reset --hard|push --force|branch -D|clean -f|checkout --`, `DROP|TRUNCATE`, `dd`, migrações) When a guarda avalia Then S ⇒ `deny`; O ⇒ `deny` com botão `Proceder` na band quando há humano presente; o botão executa exatamente o mecanismo de REQ-GRD-9 (`autor:"botao"`); sem humano presente ⇒ `deny` sem botão.
- **REQ-GRD-5 (anel escopo)** Given S com `tool ∈ {Edit, Write, NotebookEdit}` e caminho fora de `dados.arquivos` da `task.iniciada` corrente, ou S com Bash cujo redirecionamento/`sed -i`/`tee`/`cp`/`mv`/`git checkout` tem alvo fora dessa lista (tokenizador GM-7:57), ou S com ferramenta MCP de escrita When a guarda avalia Then `deny`. Given S sem task corrente Then `deny` (ADR-GRD-1). Given S com Bash que invoque `claude` em qualquer forma, ou O com `claude -p|--print` Then `deny` (sessão aninhada escapa de `agentId` — M19).
- **REQ-GRD-6 (anel segredo)** Given `tool ∈ {Read, Edit, Write, Glob, Grep, NotebookEdit}` com caminho que casa REQ-H3-1 da GM-7 (GM-7:83: `.env*`, `*.pem|key|p12|pfx`, `.npmrc`, `.netrc`, `.git-credentials`, `.pgpass`, `~/.ssh/`, `~/.aws/`, `~/.kube/`, `~/.config/gh/`, `~/.config/gcloud/`, `~/.docker/config.json`, `~/.claude/.credentials.json`, `~/.claude.json`, `~/.supabase/`, rc de shell) ou `guarda.segredoCaminhos`, ou Bash cujo texto cru cita esses caminhos ou é exibidor de REQ-H3-3 (GM-7:81–99: `printenv`, `env` sem comando, `gh auth token`, `claude mcp get`, `docker inspect`, `supabase status|projects api-keys`, `vercel env pull`) When a guarda avalia Then `deny` para O e S. Sem replay de comando. Cada item vira linha de `mustDeny`.
- **REQ-GRD-7** Given wrappers `env|command|builtin|exec|time|nice|nohup|timeout|stdbuf|sudo` (gramática GM-7:57) When os anéis destrutivo e escopo classificam Then desembrulham antes; opção desconhecida ⇒ ilegível ⇒ S `deny`; O ⇒ **fail-open declarado (G9) só nesses dois anéis**: `allow` com evento `guarda.limite {regra:"wrapper_ilegivel", hash_comando}`. Integridade, produção e segredo já avaliaram o texto cru (GRD-1) e não são afetados.
- **REQ-GRD-8** Given qualquer `deny` When a guarda responde Then evento `guarda.deny {regra, anel, agente, hash_comando}` — **nunca o texto do comando**; mensagem ao modelo = motivo + ação ("peça ao usuário `/gabarito autorizar <anel>`").
- **REQ-GRD-9** Given `/gabarito autorizar <anel> <motivo>` When `origin.kind ∈ {composer, bridge}` Then a autorização vale para o `hash_comando` do **último** `guarda.deny` daquele anel nesta sessão, uma vez, por ≤ 10 min (corte inicial; T0-9 observa se expira antes do uso); guardada em `$.state` (nunca `$.store` — cruza sessões, M4); evento `guarda.autorizacao {anel, hash_comando, motivo, autor, validade}`. Given qualquer outro `origin.kind` (união aberta, M19), ou `$.session.send` do modelo, ou `tool.call` com hash diferente Then ignorado e `deny` mantido.
- **REQ-GRD-10** Given `/gabarito ativar-guarda` de origem humana When o adaptador real roda o corpus REQ-GRD-11 e passa Then grava `$.store.guardaPronta = {build, ts}` (fora de `plugin test` — M17); Given o mod carregado com `guardaPronta.build` igual ao build atual When `session.start` Then escreve `.harness/mod-ativo.<session_id> {ts}` e o renova a cada 20 s por `$.clock.every` (corte inicial); `guard-destructive.sh` sai 0 só se o arquivo **da sua própria sessão** existe e `agora − ts < 60 s` (corte inicial; T0-5 calibra); `$.env.set("GABARITO_MOD_ATIVO", ts)` é sinal secundário com a mesma validade. Given mod descarregado ou travado Then em ≤ 60 s o `.sh` volta a negar. `.harness/.gitignore` ignora `mod-ativo.*` e `PAUSAR`.
- **REQ-GRD-11** Given o corpus (`mustDeny` = `destrutivos.txt` + `producao.txt` + casos tipados de GRD-3/5/6/13/15; `mustAllow` = `legitimos.txt` + `versionamento.txt` casos ok + `.harness` lido por `Read`) When a suíte roda Then 0 bypass em `mustDeny`; falsos positivos ≤ guarda Bash no mesmo corpus; p50 < 30 ms, p95 < 100 ms (corte inicial da T0-10, dentro de `HookBudget.ms` com folga de 100×); o teste assevera tamanho mínimo do corpus.
- **REQ-GRD-12** Given um hook de `tool.call` ou `agent.spawn` que lança, devolve forma inválida ou passa de 10 s When o motor o pula Then o `.catch` da registration devolve `{deny:"guarda falhou"}` quando `next` não foi chamado, ou `next(e)` quando já foi (M16). Given um hook de `turn.start|complete` ou `session.*` que falha (retorno sem efeito, M4) Then o `.catch` grava `$.state.guardaFalhou` e o próximo `tool.call` nega tudo exceto leitura, com status "guarda falhou em <evento>: /gabarito retomar". Teste: hook que lança e hook que dorme 11 s ⇒ ferramenta negada; `turn.start` que lança ⇒ próximo `Edit` negado.
- **REQ-GRD-13 (anel integridade)** Given O ou S com qualquer ferramenta cujo caminho (após um `$.fs.stat({resolve:true})`) ou texto cru de Bash toque, para escrita, `.harness/**`, `harness.config.json`, `.github/workflows/**`, `$.plugin.root/**`, `~/.claude/plugins/**`, `~/.claude/settings*.json`, `~/.claude.json`, `.claude/settings*.json`, `.claude/hooks/**`, o arquivo do `$.store` (T0-21), ou invoque `diario.mjs` ou `claude plugin|config|mcp` em qualquer forma When a guarda avalia Then `deny` (ADR-GRD-3). Leitura de `.harness/**` por `Read`/`cat` é `allow`. Corpus inclui glob (`rm .ha*/PAUSAR`), interpretador (`python -c`) e symlink — como casos de **O** marcados `limite` (G9), e `deny` para S.
- **REQ-GRD-14** Given `pausado:true` em `$.state` When `agent.spawn` Then `deny` com motivo "pausado"; When `tool.call` de **S** (qualquer ferramenta) Then `deny`; When `tool.call` de O que não é leitura (definição no topo) Then `deny` até `/gabarito retomar` (D7).
- **REQ-GRD-15** Given `next.trace` (lido no primeiro `tool.call` da sessão) mostrando outro plugin de tier `user` com hook em `tool.call` acima deste mod When detectado Then evento `guarda.limite {regra:"plugin_acima", nome}` + status "guarda: plugin acima"; o doctor `guarda-camada` reporta FALTA (M19: tier `user` não dá precedência; recomendação registrada = instalar por managed settings em `prepend`). Limite declarado (G9). Prova: função pura `detectaPluginAcima(trace)` com `trace` sintético (o kit não carrega outro plugin, M17); T0-1 anota um `next.trace` real.

### POU — pouso e kill switch

- **REQ-POU-1** Given `turn.complete` do loop principal (`agentId` indefinido) When o último evento de task é `task.concluida` e `$.session.usage().context.percent ≥ pouso.ctxPercent` Then marca `pouso_pendente` em `$.state` e agenda o pouso por `$.clock.after(0, fn)` (ADR-POU-1). Given o limiar atingido **sem** `task.concluida` Then só `pouso_pendente`; nunca pousa no meio da task. Given `percent === undefined` Then não pousa e status mostra "ctx ?"; evento `sessao.checkpoint {motivo:"ctx_indisponivel"}` uma vez por sessão.
- **REQ-POU-2** Given botão `Pausar`, `/gabarito pausar` (origem humana) ou arquivo `.harness/PAUSAR` (checado a cada 30 s por `$.clock.every` — corte inicial — que grava `$.state.pausado`; o `tool.call` lê só o `$.state`) When detectado Then `pausado:true`, `$.turn.abort({turnId})` do turno principal corrente (M4), `deny` de todo `tool.call` de S e de `agent.spawn` (GRD-14), evento `sessao.pausa {motivo, turno_abortado, subagentes_vivos}`. Processo de subagente já em background: comportamento medido na T0-4; até lá o `instantaneo` lista `subagentes_vivos` como limite (G9) — mas nenhum deles escreve (GRD-14).
- **REQ-POU-3** Given `pouso_pendente` When o callback de `$.clock.after(0, fn)` roda (fora de qualquer hook que o turno espere, M4) Then, em ordem e sem espera síncrona dentro de hook: (1) `sessao.pouso {motivo, ctx_percent}`; (2) ClickUp via porta `mcp` se `pouso.clickup.sincronizar`, falha ⇒ `sessao.sync_falhou {erro}` sem bloquear; (3) `project` → `instantaneo` (via CLI) → `$.state.instantaneo`; (4) `receipt`; (5) `pouso_pendente = consumido`, então `command.run({command:"clear"})` (dispara `session.end` com `reason` de `/clear` — POU-7 reconhece) e `prompt.submit({text:"retome a entrega <ID> pelo instantâneo"})`, ou `$.session.compact({instructions: instantaneo})` quando `pouso.usarCompact` e o hook está disponível; (6) `sessao.retomada {motivo:"pouso"}` gravada pelo próprio callback (não há `session.start` após `/clear`, M4); `sessao` continua a mesma (`$.session.id()` após `/clear` é anotado na T0-3). Subagentes vivos: contador em `$.state` decrementado a cada `turn.complete` com `agentId`; o pouso só começa com contador 0 (modo normal) ou após `Pausar`. Tempo total sem ClickUp < 10 s (T0-12).

## Pendências

- **ID de Iniciativa/Epic no ClickUp** — a vincular no onboarding (`--vincular`); até lá fio condutor marcado (b). Desbloqueia: rodar `gabarito-instalar` neste repo.
- **Managed orgs (M3):** se um projeto do time rodar sob managed settings, `session.compact` hook e `classic.*` não rodam no mod instalado por usuário; o caminho primário (ADR-POU-1) não depende deles, mas `session-card.sh`/`remind-orchestrator.sh` (classic) deixam de rodar — o doctor `mod-ativo` deve acusar. Desbloqueia: medir num projeto gerenciado quando existir.

- **Humano presente em `-p` com bridge** — `surfaces()` é vazio em `-p` puro (M4); com bridge anexada conta como humano presente pela definição do topo; a A2 decide se o loop autônomo em `-p` deve negar `Proceder`.
