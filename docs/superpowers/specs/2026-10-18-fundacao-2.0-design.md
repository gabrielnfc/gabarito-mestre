# Design — Gabarito Mestre 2.0 · A1 Fundação: diário de bordo, guarda tipada, pouso e status

Iniciativa: GAB-2.0 (b — ID do ClickUp a vincular no onboarding) · Epic: GAB-2.0-A "Sombra" (b) · PBIs do Epic: **GM-8 A1 Fundação (esta spec)** · GM-9 A2 Loop autônomo · GM-10 B Painel · GM-11 C Adoção/atestado · GM-12 E QA via browser.

**STATUS: DESENHO PRONTO · plano ainda não escrito.** Nada abaixo está implementado. Toda afirmação sobre o mod é **(b)** até o plano ser executado e a T0 medir. Fatos M1–M14 são **(a)**.

Escopo: a fundação sobre a qual o loop autônomo (GM-9) será construído e medido — (1) diário de bordo append-only com projeção determinística, (2) guarda de `tool.call` tipada que substitui a guarda Bash como camada primária, (3) pouso (handoff automatizado na fronteira da task) com kill switch, (4) linha de status mínima. **Sem loop autônomo:** o dono continua orquestrando; o que muda é que ele passa a ter guarda tipada, diário, retomada determinística e handoff automático. O método passa a se chamar **Fluxo Gabarito** (D2); a renomeação nos artefatos publicados é PBI próprio (Fora de escopo).

## Decisões do usuário (não reabrir)

- **D1 — Pivô.** GM-7 (hotfix 1.1.1) arquivado em `archive/GM-7` (R13); a 2.0 reaproveita D9/R1 (S lista branca, O lista negra contra acidente), R7 (acidente × disfarce), R11 e as listas de deny; H3 reduzido (segredo por caminho/padrão, sem replay). *Rejeitado:* continuar o GM-7 — o custo vinha de simular shell; o mod intercepta `tool.call` tipado antes do shell.
- **D2 — Nome.** O método chama-se **Fluxo Gabarito**; Flight Levels/Kanban só como inspiração citada. *Rejeitado:* manter o nome de terceiro (risco de marca).
- **D3 — Fatiamento.** A1 Fundação (esta) → A2 Loop → B Painel → C Adoção → E QA. *Rejeitado:* loop primeiro (sem diário não há como medir a A2) e spec única (T0 enorme antes de qualquer valor).
- **D4 — Compatibilidade.** O mod assume toda a guarda; hooks Bash viram fallback fino só do "nunca produção". *Rejeitado:* duas guardas convivendo (GM-7 de novo) e reescrever tudo sobre API instável.
- **D5 — Diário.** Journal append-only por entrega, em git, só o mod escreve; unidade de retomada = task; arquivo por entrega, dono em cada evento. *Rejeitado:* ledger markdown editado pelo modelo (frágil para reconstruir) e estado só no `$.store` (não cruza máquina, não é auditável).
- **D6 — Pouso.** Handoff automatizado na fronteira da task; X% é variável de custo medida, não limiar fixo; nunca confiar no auto-compact a 100%. *Rejeitado:* 60% fixo; compactar no meio da task.
- **D7 — Kill switch.** Pausar mata subagentes; retomar recomeça a task do início; só origem humana despausa. *Rejeitado:* pausa suave deixando subagentes terminarem.
- **D8 — Hatch.** Autorização de produção/destrutivo só por comando humano (`/gabarito autorizar`), nunca no texto do comando. *Rejeitado:* manter `GABARITO_ALLOW_*` no comando (M7: autodeclarável).
- **D9 — Piso de qualidade.** Tighten-only: TDD com RED válido + evidência, mutação no diff, CI verde, guarda — independem da spec; spec só adiciona gates. *Rejeitado:* deixar os testes a critério da spec (dev júnior sem trilho).
- **D10 — Modelos.** Orquestrador Opus 5.5; revisor Fable 5.1 (fallback Opus marcado no diário; nunca a mesma instância que implementou); implementador **a medir** (Sonnet 5.5 × Opus 5.5 `low` × Opus 5.5 `medium`, custo por task aprovada incluindo reviews); Haiku 5.5 a medir em checáveis (< 100K). Decisão da A2; registrada aqui para o diário já carregar `modelo`.
- **D11 — Spec e assinatura.** Spec sempre no repo; aprovação = evento `spec.aprovada` por e-mail em `fluxo.aprovarSpec`; plano aprovado por revisor por padrão. Mecanismo de evento entra na A1; o fluxo `/gabarito spec` é A2.
- **D12 — Descartados.** Sala multi-dev/multi-conta (M5: API não cruza contas; M12: ninguém faz) e "decisão só do sênior" durante a execução (spec aprovada já decidiu).

## ADRs

- **ADR-ARQ-1 — Adaptador único sobre `$`.** Só `hooks/mod/adaptador.ts` chama a API de mods; guarda, pouso e projeção são funções puras. Racional: API "may change between releases without notice" (README oficial). Cláusula de morte: quando a API for declarada estável, o adaptador pode ser inlined.
- **ADR-ARQ-2 — Diário em `gates/src/diario/`, não no mod.** Racional: o instalador já copia `gates/` para `tools/gabarito-gates/` do projeto; o CI do dev verifica o diário sem mod instalado e sem function hooks. Condição: T0-2 confirma que o mod importa de fora da própria pasta; senão, cópia gerada por script na pasta do mod (uma fonte, duas cópias verificadas iguais no CI).
- **ADR-GRD-1 — Fail-closed.** Config ausente, diário inválido ou erro interno da guarda ⇒ `deny`. Racional: o oposto (gateguard "allow with warning") exigiu corpus de 184 passos para provar 0 bypass. Sem cláusula de morte.
- **ADR-GRD-2 — Hooks Bash desligados pelo mod.** `guard-destructive.sh` e `guard-versioning.sh` saem com 0 quando o marcador do mod está presente; `guard-production.sh` nunca desliga. Cláusula de morte: ao fim da A1, se o corpus comparativo (T0-9) mostrar o mod ≥ Bash, os dois `.sh` são removidos em PBI próprio.
- **ADR-POU-1 — Caminho primário do pouso é `/clear` + injeção.** Racional: M3 — o hook `session.compact` não roda em org gerenciada. `$.session.compact({instructions})` é otimização opcional quando disponível. Cláusula de morte: se a Anthropic liberar o hook para plugins de usuário, inverter o padrão.
- **ADR-DIA-1 — Evento recusado, nunca redigido.** Canário de segredo ⇒ append falha; o chamador corrige. Racional: diário vai para `main`; redação silenciosa esconde o bug que gerou o vazamento.

## Requisitos

### DIA — diário de bordo

- **REQ-DIA-1** Given uma entrega `<ID>` When qualquer componente grava Then o evento vai para `.harness/entregas/<ID>/events.jsonl` com `{v, seq, ts, linhagem, tipo, autor, sessao, agente, modelo?, dados, hash_anterior, hash}`; `seq` estritamente crescente; `hash` = sha256 canônico; `hash_anterior` = `hash` do anterior. Gate: `gates/test/diario.test.ts`.
- **REQ-DIA-2** Given um `tipo` fora do vocabulário (`spec.aprovada`, `plano.aprovado`, `task.iniciada|concluida|reaberta`, `review.veredito`, `ci.resultado`, `guarda.deny|autorizacao`, `custo.medicao`, `sessao.inicio|pouso|pausa|retomada|checkpoint|sync_falhou`) ou `dados` fora do esquema do tipo When `append` Then recusa com `bad_schema`. Allowlist default-deny.
- **REQ-DIA-3** Given `dados` ou qualquer campo com padrão de credencial (regras de `redact()` do flightdeck + canários do ECC) When `append` Then recusa com `secret_canary` e nada é gravado (ADR-DIA-1).
- **REQ-DIA-4** Given dois processos gravando na mesma entrega When o lock `wx` falha Then o segundo tenta 3× com espera; depois erro `locked`. Lock órfão: `diario.mjs unlock` grava `sessao.checkpoint {motivo:"unlock manual"}`.
- **REQ-DIA-5** Given o journal When `verify` Then devolve ok ou o primeiro índice quebrado com código ∈ {`broken_link`, `truncated_tail`, `reordered`, `bad_schema`, `secret_canary`}; qualquer código ⇒ exit 1.
- **REQ-DIA-6** Given journal verificado When `project` Then devolve estado `{entrega, spec, plano, taskAtual, tasksAprovadas, tasksReabertas, pr, ci, custo:{task, entrega}, guarda:{denies}, proximoPasso, ponteiros}` + `projection_hash`; mesma entrada ⇒ mesma saída (determinístico, testado).
- **REQ-DIA-7** Given o estado projetado When `instantaneo` Then texto em formato fixo (seção "Projeção → instantâneo" do design) com ≤ 1.500 tokens; acima disso, até 3.000 com aviso `instantaneo_grande`; acima, erro. Medido por `count_tokens` na T0-6.
- **REQ-DIA-8** Given `diario.checkpointACada` eventos desde o último checkpoint When `append` Then grava `sessao.checkpoint` com a projeção embutida; `project` parte do último checkpoint.
- **REQ-DIA-9** Given `task.concluida` When `dados.evidencia` não traz a tabela `[{garantia, teste, tipo, resultado, comando}]` com ≥ 1 linha Then recusa com `bad_schema` (D9 — piso).
- **REQ-DIA-10** Given uma PR When `receipt` Then `.harness/entregas/<ID>/recibo.json` = `{root_hash, eventos, diff_digest, gerado_em}`; formato aceita assinatura destacada sem mudar campos.
- **REQ-DIA-11** Given duas sessões simultâneas na mesma entrega When ambas gravam Then cada uma usa `events.<sessao>.jsonl`; `project` junta por `ts` e marca `concorrente:true`.

### GRD — guarda de `tool.call`

- **REQ-GRD-1** Given qualquer `tool.call` When a guarda decide Then o veredito é `deny` ou `allow`; a cadeia de regras só aperta (`stricter(chain, verdict)`); `rewrite` não é emitido na A1.
- **REQ-GRD-2** Given `e.agentId === undefined` Then o chamador é O (orquestrador): lista negra contra acidente (R7); senão é S: lista branca. Teste: mesmo comando, dois vereditos.
- **REQ-GRD-3 (anel produção)** Given comando/caminho/ferramenta com host, URL ou credencial de produção (regras de `guard-production.sh` portadas), `git push|merge` para `main`/`prod*`, ou ferramenta `mcp__<servidor>__*` com servidor em `guarda.mcpProducao` Then `deny` para O e S, sem hatch no texto (D8). Corpus: `producao.txt` + casos MCP.
- **REQ-GRD-4 (anel destrutivo)** Given Bash classificado destrutivo (trechos do gateguard M9 + listas GM-7: `rm -rf`, `git reset --hard|push --force|branch -D|clean -f|checkout --`, `DROP|TRUNCATE`, `dd`, migrações) Then S ⇒ `deny`; O ⇒ `deny` com botão `Proceder` na band quando há humano na sessão (`$.session.surfaces()` tem terminal/desktop/vscode); sem humano ⇒ `deny`.
- **REQ-GRD-5 (anel escopo)** Given S com `tool ∈ {Edit, Write, NotebookEdit}` e caminho fora de `dados.arquivos` da `task.iniciada` corrente Then `deny`. Given sem task corrente Then `deny` (ADR-GRD-1).
- **REQ-GRD-6 (anel segredo)** Given `tool ∈ {Read, Edit, Write, Glob, Grep}` com caminho casando `.env*`, `*.pem`, `*.key`, `id_rsa*`, `~/.aws/*`, `~/.ssh/*`, `*.p12`, `*.jks` ou `guarda.segredoCaminhos`, ou Bash cujo texto cita esses caminhos/nomes de variável de credencial Then `deny` para O e S. Sem replay de comando.
- **REQ-GRD-7** Given wrappers `env|command|builtin|exec|time|nice|nohup|timeout|stdbuf|sudo` Then desembrulha antes de classificar; opção desconhecida ⇒ ilegível ⇒ S `deny`, O limite declarado (R7).
- **REQ-GRD-8** Given qualquer `deny` Then evento `guarda.deny {regra, anel, agente, hash_comando}` — **nunca o texto do comando**; mensagem ao modelo = motivo + ação ("peça ao usuário `/gabarito autorizar`").
- **REQ-GRD-9** Given `/gabarito autorizar <anel> <motivo>` digitado pelo humano When o próximo `tool.call` do anel ocorre em ≤ 10 min ou é o próximo comando Then `allow` uma vez; evento `guarda.autorizacao {anel, motivo, autor, validade}`. O modelo não tem comando equivalente (`command.run` só por prompt humano; teste: `$.session.send` do modelo pedindo autorização é ignorado).
- **REQ-GRD-10** Given mod carregado Then `$.env.set("GABARITO_MOD_ATIVO","1")` e arquivo `.harness/mod-ativo`; `guard-destructive.sh` e `guard-versioning.sh` leem um dos dois e saem 0 (ADR-GRD-2). T0-5 decide qual sinal fica.
- **REQ-GRD-11** Given o corpus (`mustDeny` = destrutivos + producao + casos tipados; `mustAllow` = legitimos + versionamento-ok) When a suíte roda Then 0 bypass em `mustDeny`; falsos positivos ≤ guarda Bash no mesmo corpus; p50 < 30 ms, p95 < 100 ms (T0-9/10).

### POU — pouso e kill switch

- **REQ-POU-1** Given `turn.complete` do loop principal com `task.concluida` como último evento de task When `$.session.usage().context.percent ≥ pouso.ctxPercent` Then executa o pouso (REQ-POU-3). Given o limiar atingido **sem** `task.concluida` Then só marca `pouso_pendente` em `$.state`; nunca pousa no meio da task.
- **REQ-POU-2** Given botão `Pausar`, `/gabarito pausar` ou arquivo `.harness/PAUSAR` (checado em `turn.start` e a cada 30 s por `$.clock.every`) Then pouso em modo pausa: `$.turn.abort` em cada subagente vivo, evento `sessao.pausa {motivo, subagentes_abortados}`.
- **REQ-POU-3** Given pouso Then, em ordem: (1) subagentes — modo normal aguarda `turn.complete` de cada; (2) `sessao.pouso {motivo, ctx_percent}`; (3) ClickUp via `$.mcp.call` se `pouso.clickup.sincronizar`, falha ⇒ `sessao.sync_falhou` sem bloquear; (4) projeção → instantâneo; (5) `/clear` + `$.prompt.submit(instantaneo)` (ADR-POU-1), ou `$.session.compact({instructions})` quando o hook está disponível e `pouso.usarCompact`; (6) `receipt`. Tempo total sem ClickUp < 10 s (T0-12).
- **REQ-POU-4** Given `/gabarito retomar` ou botão Then `verify` do diário (falha ⇒ erro visível, sem retomar), instantâneo, injeção, e `task.reaberta` para a task que estava aberta — recomeço do início.
- **REQ-POU-5** Given `pausado:true` em `$.state` When o modelo envia prompt/`session.send` pedindo retomada Then ignorado; só `command.run` (humano) ou remoção do arquivo despausa.
- **REQ-POU-6** Given `session.start` Then `verify`; ok ⇒ instantâneo injetado por `prompt.compose` (`scope: session`); falha ⇒ aviso na status e sem instantâneo (fail-closed: nada falso entra no contexto).
- **REQ-POU-7** Given `session.end` Then pouso leve: diário + instantâneo + recibo, sem `/clear`.

### STA — status

- **REQ-STA-1** Given eventos no diário ou `session.measure` Then `$.ui.status("<ID> · T<n> a/b · ctx NN% · US$ x,xx · guarda k")`.
- **REQ-STA-2** Given sessão com surface que desenha Then band `AbovePrompt` com `Pausar`/`Retomar` e o motivo quando pausado; sem pane na A1.

### CFG — configuração

- **REQ-CFG-1** `onboarding-config.mjs` grava as seções `diario {dir, checkpointACada}`, `pouso {ctxPercent, usarCompact, clickup.sincronizar}`, `guarda {mcpProducao[], segredoCaminhos[]}`, `fluxo.aprovarSpec[]`, `fluxo.aprovarPlano`, `testes {afetados, suiteCompleta}`, `custo {tetoTaskUsd:null, tetoEntregaUsd:null}` em `harness.config.json`, cada uma com `resolvidoEm`. Seção ausente ⇒ fail-open **declarado** (G9) só para `pouso.clickup`, `testes` e `custo`; `guarda` e `diario` ausentes ⇒ guarda nega (ADR-GRD-1).

### PIS — piso de qualidade

- **REQ-PIS-1** Given `gabarito-conformidade` sobre uma spec sem seção "Testes e gates" com ao menos um teste por requisito Then achado "testes não declarados" (spec não passa — 0 achado).
- **REQ-PIS-2** Given relatório do implementador com padrão de racionalização (`pre-existing bug`, `skipping tests for now`, `tests are failing but`, `will fix later`) Then o orquestrador reprova antes de despachar o revisor; evento `review.veredito {rodada:0, motivo:"racionalizacao"}`.
- **REQ-PIS-3** Given `testes.afetados` configurado Then o implementador roda só os afetados no RED/GREEN e a `suiteCompleta` uma vez ao fechar a task; sem config, suíte completa sempre (fail-open declarado).

### CI / DOC — pipeline e doctor

- **REQ-CI-1** Jobs novos: `diario — verify` (toda PR, `diario.mjs verify` em todas as entregas tocadas), `mod — validate + test` (`claude plugin validate --strict` + `claude plugin test hooks/mod` + `tsc -p hooks/mod`), `guarda — corpus` (REQ-GRD-11), `skills — quick_validate` (M13, sobre as 4 skills). Template `templates/gabarito.yml` ganha os mesmos jobs para o projeto do dev.
- **REQ-DOC-1** Doctor: `M16 mod-ativo` (function hooks carregam: sim/não/indeterminado), `M17 guarda-camada` (mod | bash-fallback | nenhuma), `M18 diario-integro` (`verify` ok e último checkpoint há < `checkpointACada` eventos), `M19 recibo-presente` (PR aberta tem `recibo.json` coerente com o diff).
