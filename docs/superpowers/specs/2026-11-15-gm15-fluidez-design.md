**REQ-ENT-1 Merge na `main` encerra a entrega, e o encerramento não volta sozinho (prioridade 1).**
- (a) **Medida** (c). "Subiu para a `main`" = PR mergeado com base `main` cujo head casa o ID ancorado (`--head` de hoje) ou cujo título casa o ID (`gh pr list --base main --state merged --search "<ID> in:title"`). Isso grava `fato.medido pr {numero, estado, branch, base, via: 'head'|'titulo'}`, e a forma ganha `base` e `via` opcionais. Na releitura, `prs()` aceita o PR que veio por `via: 'titulo'` mesmo com head sem ID; o descarte por head vale só para `via: 'head'` ou para o fato sem `via`. Todo PR que o diário dá como `aberto` é remedido por número (`gh pr view <n>`); se o head não casa o ID, sai da entrega.
- (b) **Fato legado.** Um `fato.medido pr` sem `base` nunca encerra a entrega, mesmo `mergeado` (é o caso do #7 do F3). Ele continua valendo só para a fase PR da trilha, como hoje.
- (c) **Estado de encerramento.** `painel.mjs medir` grava `entrega.encerrada {entrega, pr, via: 'head'|'titulo', mergeado_em, versao?}` quando acha um PR com base `main` válido por (a) que ainda pode encerrar (regra de re-encerramento abaixo). A origem é `(automático)` (REQ-LNG-1 `entrega.*`), o evento vai para `dirEntrega(raiz, id)` e nunca para `_sem-id`, e uma duplicata de duas sessões é tolerada (a projeção usa o 1º). **Papel novo do `medir`, declarado:** ele deixa de gravar "só `fato.medido`" (`painel.mjs:7`) e grava também `entrega.encerrada`.
