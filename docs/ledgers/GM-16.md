- **RD-1 (MAJOR) A branch do aviso `pbi-mergeado-aberto` é a base da entrega, nunca `versionamento.branchPadrao`.** Fato (a): `versionamento.branchPadrao` é regex de nome de branch de feature (`plugins/gabarito-mestre/gates/scripts/versionamento-check.mjs:32`, `:68`; literal é erro em `onboarding.mjs:48`, `:490-492`). Lida como nome, `git log <regex>` falha e o aviso vira "não conferido" em todo repositório com o padrão; a fixture com trunk `main` passaria verde mentindo. Decisão: o doctor **reusa** `resolverBaseEntrega` (`gates/src/entrega.ts:95-110`, via `dist/entrega.js`), a mesma fonte que a entrega usa para a base do PR. Porquê: (1) "mergeado" quer dizer "chegou na base em que a entrega integra", e essa base já tem dono no código; (2) uma regra nova para a branch principal seria a 3ª leitura divergente do mesmo conceito; (3) a branch default do remoto sozinha erra em repositório cuja base de integração é outra, caso que o onboarding já trata ao gravar `entrega.base` (`onboarding.mjs:851`). O resolvedor chuta `main` quando nada foi declarado; o doctor não herda o chute: base cuja ref não existe (`refs/remotes/origin/<base>`, depois `refs/heads/<base>`) ⇒ "não conferido", nunca `main` nem "ok". Testes obrigatórios: `doctor-mergeado-config-default` (regex padrão + trunk ≠ `main` ⇒ avisa), `doctor-mergeado-base-inexistente`, `doctor-mergeado-base-da-entrega`; mutações M5h, M5i, M5j.
